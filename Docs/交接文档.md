# 美食收藏与随机选择 — 项目交接文档

## 项目概述

**项目名称**: 美食收藏与随机选择 (food-picker)

**功能**: 两个用户共享的美食和游玩地点收藏工具，支持随机挑选功能。用户可以：
- 添加/编辑/删除美食和游玩地点
- 按城市、区域、标签筛选后随机选择
- 记录随机历史
- 多设备数据同步

**当前状态**: ✅ 已完成并部署上线

**部署地址**: https://pgst9h8g4n-hub.github.io/food-picker/

**源码仓库**: https://github.com/pgst9h8g4n-hub/food-picker

## 关键设计决策

### 1. 数据存储方案演变

| 阶段 | 方案 | 状态 | 原因 |
|------|------|------|------|
| 初始 | Supabase + Supabase Auth | ❌ 已废弃 | Supabase 实例被删除，国内网络不可达 |
| 中期 | Railway + Turso | ❌ 未实现 | Railway 试用到期，国内网络不稳定 |
| 当前 | localStorage + GitHub Gist | ✅ 运行中 | 国内可访问，免费，零运维 |

### 2. 认证方案

- **不使用** Supabase Auth（已废弃）
- **使用** 简单密码存储在 localStorage
- 密码哈希使用 SHA-256 + salt（简单实现，非生产级）
- 密码仅用于生成 Gist ID 和加密密钥

### 3. 多设备同步方案

- **不使用** 传统数据库（Supabase/Turso 网络问题）
- **使用** GitHub Gist API 作为 Key-Value 存储
- 数据使用 Web Crypto API (AES-256-GCM) 加密
- 加密密钥由用户密码派生
- 存储为私有 Gist，仅所有者可访问

### 4. 部署方案

- **不使用** Vercel（国内网络超时）
- **使用** GitHub Pages（国内可访问）
- GitHub Actions 自动构建部署
- Vite base 路径配置为 `/food-picker/`

## 同步使用说明

### 获取 GitHub PAT

1. 访问 https://github.com/settings/tokens
2. 点击 "Generate new token" → "Generate new token (classic)"
3. 只勾选 `gist` 权限
4. 复制生成的 token（以 `ghp_` 或 `github_pat_` 开头）

### 启用同步

1. 在登录页面粘贴 GitHub PAT
2. 点击"连接"按钮
3. 显示 ✓ 表示连接成功
4. 登录/注册后数据自动同步

### 同步策略

- 登录时自动同步（如果已启用）
- 主页有手动同步按钮
- 云端数据优先，本地新增数据合并到云端
- 冲突解决：简单的 last-write-wins 策略

## 注意事项

1. **数据持久化**：所有数据存储在当前用户的浏览器 localStorage，清缓存会丢失
2. **同步安全**：加密使用 Web Crypto API，但密码哈希是简单实现，不适合高安全场景
3. **GitHub Rate Limit**：Gist API 有速率限制（未认证 60次/小时，认证 5000次/小时）
4. **国内网络**：GitHub Pages 和 Gist API 国内可直连，无需代理
5. **旧数据**：原 Supabase 项目已删除，如用户能找回数据，可通过控制台手动导入
